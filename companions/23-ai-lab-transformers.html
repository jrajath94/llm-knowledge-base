Unit 1 · The reason

Why this category exists

From the lesson 23-ai-lab-transformers.html, opening section

Near all modern AI products are a transformer with text plumbing around it: chatbots, code assistants, search copilots, and the retrieval systems of the next unit share one architecture. The reader builds that architecture by hand in these labs, because a research engineer cannot treat the transformer as a black box.

Four failures are routine without this unit. Attention reads as magic, so a model that ignores context gets guesswork instead of diagnosis. Training collapses with no visible cause: loss spikes and exploding gradients, with the fix a scheduler or a clip threshold the reader never learned. Tokenizers surprise: a prompt costs twice the estimate because words split in unexpected places. And inference cost explodes when a naive decode loop recomputes all history per token.

Week 9 builds the foundations the attention era replaced and reused: embeddings, recurrent networks as the sequential baseline, a full text classification lab, and the softmax and cross-entropy machinery. Week 10 goes from the block to a trained model to affordable inference: block internals, training dynamics, tokenization internals, a tiny autoregressive language model trained offline end to end, fine-tuning, and attention complexity work. Unit 2 · Core ideas, worked end to end

1. Self-attention and the scaled dot-product

From the lesson 23-ai-lab-transformers.html, core ideas

Self-attention lets every token build a representation as a weighted mix of all token representations, itself included. The concrete form is scaled dot-product attention: Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V. Queries, keys, and values are three separate linear projections of the same input. Keys act as labels, the query states the search, and values carry the content.

Recurrent networks came first and set the problem. An RNN processes tokens one at a time and squeezes history into a fixed-size hidden state, so long-range signal fades as gradients travel back through every step. Attention replaces the single bottleneck with direct pairwise links: an O(1) path between any two tokens in place of an O(n) chain.

The steps are exact. Project X into Q, K, V. Compute the score matrix S = Q K^T, one entry per token pair. Scale by 1 / sqrt(d_k). In a causal model, add the causal mask before the softmax. Softmax each row so weights sum to one. Multiply the weights by V. Multi-head attention runs the whole procedure h times in parallel with separate projections and concatenates the results, so each head can track a separate relation type.

Two traps close the concept. Attention weights are not explanations: a high weight marks a route for information, not a cause for a prediction. And the scale step is load-bearing: raw dot products grow with dimension, the softmax saturates, and gradients vanish. The interview bar is a from-scratch build in about fifteen minutes plus the scale defense.

0.576top attention weight in the worked three-token row
Nugget 1 · The worked attention row From the lesson Concept 1 of the unit
The lesson

For one query against three keys with d_k = 2, scaled scores [0.707, 0, -0.707] softmax to weights [0.576, 0.284, 0.140].

Why it matters. The output is a weighted sum of value vectors with those exact shares. The scale step keeps the softmax out of saturation, where gradients die.

Transfer. Run this three-token case by hand before you read any attention code. The code is this arithmetic at scale, with a mask added.

The lesson

In a causal model, future positions take negative infinity before the softmax, never after.

Why it matters. A mask after the softmax leaves leaked probability mass in the denominator. The model trains on answers it must not see, and no eval on clean data exposes the leak.

Transfer. Audit mask placement in every causal build you review. Order is the whole rule, and the bug is silent.

2. The transformer block: residuals, normalization, and where position comes from

From the lesson 23-ai-lab-transformers.html, core ideas

A transformer block is one repeated unit. In the pre-norm layout the labs use, a block computes y = x + MHA(LayerNorm(x)) and then z = y + FFN(LayerNorm(y)). The residual adds the input back to the sublayer output. LayerNorm rescales each token vector to zero mean and unit variance. The FFN is a two-layer MLP that expands from d to 4d and back, with GELU in the middle.

Position enters by injection, because attention alone is permutation-equivariant: shuffle the input tokens and the outputs shuffle in the same way, with no sense of order. The lab uses sinusoidal encodings, PE(pos, 2i) = sin(pos / 10000^(2i/d)) and PE(pos, 2i+1) = cos(pos / 10000^(2i/d)), added to the embeddings before block 1.

Depth is the second problem the block solves. Stacks of attention and FFN layers lose gradients at depth, the same failure the deep learning unit diagnoses. Residuals give each gradient a clean identity path around each sublayer, and normalization keeps activations in a range the next layer can use. Without both, a 12-block model does not train.

The pre-norm versus post-norm order is the graded detail. The original transformer normalizes after the residual. Modern models normalize before, and pre-norm trains with more stability at depth. The parameter count for one block sits in Nugget 2.

3.1Mparameters in one block at d model 512
Nugget 2 · The FFN holds the capacity From the lesson Concept 2 of the unit
The lesson

At d_model = 512 with 8 heads, one block holds about 1.0M attention parameters and about 2.1M FFN parameters, about 3.1M in total.

Why it matters. The feed-forward network, not attention, holds most of the parameters and most of the stored knowledge. Twelve blocks reach about 37M parameters.

Transfer. Count parameters block by block in any design answer. The count exposes where capacity sits and what a size claim costs.

3. Tokenization and embeddings: text becomes numbers, numbers become meaning

From the lesson 23-ai-lab-transformers.html, core ideas

A tokenizer converts raw text into a sequence of integer ids, and an embedding converts each id into a dense vector. BPE starts from single characters and merges the most frequent adjacent pair again and again until the vocabulary reaches the target size. Frequent strings stay whole as subword tokens. Rare words split into pieces.

The design pressure is a three-way trade. Word-level vocabularies explode and break on unseen words. Character-level sequences stay tiny in vocabulary and grow so long that quadratic attention cost bites. Subwords split the difference: a bounded vocabulary in the tens of thousands with near zero out-of-vocabulary failure, because any unseen string decomposes into known pieces.

The lab builds embeddings two ways and compares them. PPMI with SVD builds a word-by-context co-occurrence matrix, keeps positive associations, and factorizes the matrix into dense vectors. SGNS trains a small classifier to predict context words against random negative samples, at lower cost on large corpora. Both solve king - man + woman near queen by cosine similarity, and the lab comparison shows each method ahead on separate relation types: no method wins everywhere.

The traps are practical. Tokens are not words: a lead space changes the id, numbers split at odd points, and non-English text can carry far worse fertility at a direct cost in money. And a tokenizer change after training is barred: ids index the embedding matrix, so a new tokenizer orphans every row the model learned.

Unit 5 · Core ideas

4. Attention economics and training stability: the two cost centers

From the lesson 23-ai-lab-transformers.html, core ideas

Two bills dominate transformer work. The inference bill is attention economics. Prefill processes the prompt once at O(n^2 d). Naive decode repeats that work per token. The KV cache stores keys and values per layer, so each decode step computes one new row at O(n d) and attends over the cached history. Tiled attention goes one step further and never writes the n by n score matrix at all.

The training bill is stability. Warmup ramps the rate over the first steps and blocks oversize early jumps. Cosine decay anneals the rate and ends late oscillation. Global-norm clipping rescales a spike gradient. AdamW decouples weight decay from the adaptive step. The lab recipe warms up to a peak rate near 3e-4 over the first 2,000 steps, decays by cosine toward 3e-5, and clips the global norm at 1.0. A stable softmax, exp(x - max(x)) over sum(exp(x - max(x))), guards the loss itself.

The cache numbers sit in Nugget 3 and Nugget 4. The trap closes the concept: the KV cache does not make generation free. Decode becomes memory-bandwidth bound, and the cache itself claims gigabytes per sequence, so cache size caps batch size at serving time.

2.1 GBKV cache per sequence in the worked 32-layer model
Nugget 3 · The cache caps the batch From the lesson Concept 4 of the unit
The lesson

A 32-layer, 32-head model at context 4096 in fp16 holds a KV cache of about 2.1 GB per sequence.

Why it matters. Cache size, not compute, sets the cap on concurrent sequences at serving time. Each new sequence claims gigabytes before it generates one token.

Transfer. Size the cache before you quote a concurrency number. The arithmetic is 2 x layers x heads x head dimension x context x bytes.

34 GBscore matrix size that tiled attention never writes
Nugget 4 · The matrix nobody writes From the lesson Concept 4 of the unit
The lesson

The full attention score matrix for the same model would take 34 GB if a naive method wrote it to memory.

Why it matters. Tiled attention never writes the matrix. Blocks stream through fast on-chip memory with an online softmax, and the output matches naive attention exactly.

Transfer. Treat memory traffic as a first-class cost. At long context, the matrix you avoid is worth more than the flops you save.

Unit 8 · The gate

Interview clearance

From the lesson 23-ai-lab-transformers.html, interview clearance

The design prompts demand builds, not summaries. Implement scaled dot-product attention with a causal mask in NumPy and state the per-head rule d_k = d_model / h. Draw one pre-norm block with every tensor shape at d_model = 512 and h = 8, and count the block parameters. Compute a KV cache size for a given model and context, and name the resource the cache caps.

The defense prompts carry the rest. Explain BPE merge learning on a three-word corpus and state the breakage from a post-training tokenizer change. Defend a training recipe end to end: warmup, cosine decay, clip points, and AdamW over Adam.

The graded answers are short. Scale by sqrt(d_k) because dot products grow with dimension and saturate the softmax. Mask before the softmax, as negative infinity. Cache for the worked model: about 2.1 GB per sequence, and memory, not compute, caps concurrency.
