point-in-timethe rule for offline features: no future data
Nugget 1 · Point-in-time is the rule From the lesson Task 3 of the lab
The lesson

Offline features must use only data at or before the event time for each label row. That rule is point-in-time correctness.

Why it matters. A feature that reads the future hands the model the answer at train time. Live service has no future data, so the train score is fiction.

Transfer. Prove the as-of time for each feature before you trust an offline score. The proof is part of the feature review.

inflatedstate of the metric under leakage
Nugget 2 · Leakage inflates the metric From the lesson Task 5 of the lab
The lesson

The lab builds leaky features on purpose and watches the evaluation metric rise. The rise is the lesson.

Why it matters. A metric gain from leakage is a debt, not a win. The model fails in production at the exact point where the leaked signal ends.

Transfer. Treat a surprise metric jump as a leakage alarm. Audit the feature times before you celebrate the gain.

Nugget 3 · Two feature sets, one truth test From the lesson Task 5 of the lab
The lesson

The evaluation compares two feature sets on the same labels: the point-in-time set and the leaky set.

Why it matters. Same labels and same model isolate the cause. The metric gap between the sets is the size of the leakage effect.

Transfer. Run correct and suspect feature sets side by side. The gap tells you the cost of the flaw in one number.

Unit 7 · The online store

Task 6: 4 — Online store simulation + skew check

From the lesson notes/w13-d2-feature-store-patterns.html, task 6

Step four simulates the online store and runs the skew check. The check compares train features against service features for the same events.

The page notes one subtle cause: offline and online features can differ even without explicit bugs, when the paths compute at distinct as-of times.

2stores compared in the skew check: offline and online
Nugget 4 · Skew is a time bug in disguise From the lesson Task 6 of the lab
The lesson

Offline and online features can differ with no code bug at all, when the two paths compute at distinct as-of times.

Why it matters. Skew means train and serve feed the model distinct inputs for the same event. The model then meets a new input pattern in production.

Transfer. Add a skew check to each feature launch. Compare offline and online values for the same events before rollout.
