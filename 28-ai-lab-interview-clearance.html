Round (a): Python ML coding from scratch

The DeepMind signature round and a growing piece of OpenAI loops: implement ML primitives with no libraries and no AI assistance, and make the code run. Interviewers watch the narration as much as the code: state shapes, state complexity, and verify behavior with a quick check.

A1. Implement attention with masking and KV caching. (DeepMind ML coding, candidate-reported.)

Worked answer. Write the three projections Q, K, V from the input, scale the QK scores by the square root of the key dimension, add the causal mask before the softmax (masked positions get negative infinity, and in fp16 use the dtype minimum rather than a large negative literal), softmax over the last axis, and multiply by V. For KV caching: at decode step t you only compute the query for the new token and attend over the cached keys and values, which turns each step from quadratic in the sequence length into linear. A <dfn>KV cache</dfn> is the stored keys and values from previous tokens, reused so each decode step avoids recomputation.

Trap. Applying the mask after the softmax, which does nothing; or using a large negative float that underflows in fp16. Also forgetting to narrate the complexity change the cache buys.

A2. Implement multi-head self-attention from scratch, causal, no nn.MultiheadAttention. (DeepMind ML coding, representative.)

Worked answer. Multi-head is a reshape, not new math: one fused QKV projection, then view the result as (batch, heads, tokens, head-dim) and run standard scaled dot-product attention per head with the causal mask before softmax, then merge heads back. Get three things right: the sqrt(d_k) scaling (it keeps logit variance near 1 at initialization so the softmax does not saturate), the head reshape bookkeeping, and the mask placement. Narrate complexity: O(T^2 D) compute and O(H T^2) attention memory, and note that FlashAttention removes the T-by-T materialization by tiling. Verify causality by perturbing a later position and checking that position 0 output is unchanged.

Trap. Forgetting the scaling factor or the mask, and botching the reshape so heads mix. Also stating complexity without being asked is a plus, not a distraction.

A3. Implement a transformer from scratch with PyTorch. (DeepMind ML coding, candidate-reported "historian question".)

Worked answer. Stack the pieces in order: token embedding, positional encoding, then repeated blocks of multi-head attention plus residual plus layer norm plus MLP plus residual, a final norm, and the output projection. Cover the three things interviewers probe: causal masking inside attention, Pre-LN versus Post-LN placement (Pre-LN normalizes before the sublayer and trains more stably at depth), and weight initialization. Know why transformers use LayerNorm instead of BatchNorm: batch statistics are unstable across variable-length sequences, while LayerNorm normalizes per token and is sequence-length agnostic.

Trap. Reciting the block order without being able to justify Pre-LN versus Post-LN or LayerNorm versus BatchNorm. The justifications are the graded part.

A4. Implement a FlashAttention forward pass with masking. (OpenAI research-engineer ML coding, candidate-reported.)

Worked answer. Same mathematics as standard attention, tiled so the n-by-n score matrix is never materialized: process blocks of queries against blocks of keys and values, and recompute the tiles in the backward pass instead of storing them. The numerical core is the online softmax: track a running maximum and a running sum per tile so the computation stays stable without the full row. The win to articulate is IO-awareness: the bottleneck moves from HBM bandwidth to compute because tiles live in fast on-chip SRAM.

Trap. Describing it as "faster attention" without the IO argument, or forgetting the backward recompute tradeoff. Masking must be applied per tile, not as an afterthought.

A5. Implement nucleus (top-p) sampling. What failure mode of top-k does it fix? (DeepMind ML coding, representative.)

Worked answer. Top-k fails because the right candidate-set size depends on the context: in a peaked distribution the top-k admits junk tokens, in a flat distribution it excludes good ones. Nucleus sampling keeps the smallest set of tokens whose cumulative probability reaches p: sort by probability descending, accumulate until the sum crosses p, keep the token that crosses the threshold, and always keep the top token. Temperature scales the logits before the softmax; p truncates after it. Complexity is O(V log V) for the sort, which is why production samplers pre-filter with a small top-k first. For evals, pin temperature to 0 or report variance across seeds, because sampling parameters interact with reproducibility.

Trap. The off-by-one that drops the threshold-crossing token, and confusing temperature (applied before softmax) with truncation (applied after).

A6. Derive the softmax plus cross-entropy gradient; then the gradient of a custom loss coupling two models. (DeepMind ML coding and breadth, candidate-reported.)

Worked answer. For softmax with cross-entropy, substitute the softmax Jacobian into the chain rule and watch everything cancel: the gradient is prediction minus target (p_i minus y_i). Fuse them numerically with the log-sum-exp trick: subtract the maximum logit before exponentiating, keep the computation in log space, and compute in fp32 from logits even when the model runs in fp16. For two coupled models, apply the chain rule through both computation graphs and state explicitly which terms interact; in large-vocabulary language models an extra z-loss term is sometimes added to stop the log-partition function from drifting.

Trap. Deriving the gradient without mentioning numerical stability, or hand-waving the coupled-model chain rule instead of naming the interacting terms.

A7. Build a rate limiter; every ten minutes the interviewer adds a requirement: per-tenant limits, burst allowances, then a sliding window. (Anthropic progressive-spec assessment; OpenAI variant: extend to multiple gateway instances.)

Worked answer. Start with the simplest correct thing behind a narrow interface, allow(tenant, now) returning a bool: the interface is the insurance policy against the coming requirements. Implement a fixed window first, then a token bucket (refill rate plus capacity) for bursts, then a sliding window with a deque of timestamps per tenant if memory allows. For multiple instances, extend in order of consistency cost: split the rate across N nodes, centralize in Redis with Lua-script atomicity, or run hybrid local buckets with async sync. State fail-open versus fail-closed explicitly, use a monotonic clock (never wall clock), and budget time per level: a working level 3 beats an elegant level 2.

Trap. Over-engineering level 1 and running out of time, or using wall-clock time (breaks across clock adjustments). The graded skill is absorbing new requirements without the code collapsing.

A8. Run an LLM call over 50,000 documents. The API allows about 100 concurrent requests and occasionally returns 429s and timeouts. Write the Python. (Anthropic practical coding, representative.)

Worked answer. Use asyncio with a semaphore capping concurrency at 100, retries with exponential backoff and jitter, and per-item error isolation so one poison document cannot kill the batch. Threads also work (the workload is IO-bound and the GIL releases on network IO), but asyncio handles 100-plus in-flight requests with less overhead; multiprocessing is the wrong tool here. Separate retryable errors (429, 5xx, timeouts) from non-retryable ones (400, content policy), and add checkpointing, a spend budget cap, and bounded queues if results are large.

Trap. Retrying non-retryable errors forever, or letting one bad document crash the batch. Also forgetting the spend cap: at 50,000 calls the budget is a correctness issue.

A9. Build core business logic from a growing spec (banking transactions; longest-running function from stack traces). (Anthropic assessment, candidate-reported.)

Worked answer. The interviewer adds edge cases as you go, so clean modular code that absorbs new requirements beats a pre-optimized first version. A10. Design an LRU cache with TTL eviction. (Anthropic OA-style; OpenAI SWE/RE coding, candidate-reported.)

Worked answer. A hash map plus a doubly linked list gives O(1) get and put with recency ordering: the map finds entries, the list maintains the order. Store an expiry timestamp per entry and evict lazily on access (or with a periodic sweep); the capacity policy evicts the least recently used among unexpired entries. State the time complexity of each operation explicitly.

Trap. Forgetting the TTL interaction with recency: an expired entry must not be returned as a hit, and the eviction policy must skip expired entries when choosing victims.

A11. Refactoring exercise: 120 lines of working but messy code with passing tests. Improve the architecture without breaking them. What do you change first? (OpenAI coding round, representative.)

Worked answer. First move: read, do not type. Map what the code does and which tests pin which behaviors. Prioritize by risk-to-value: fix dangerous things first (shared mutable state, swallowed exceptions, hidden side effects), then carve single-responsibility functions, and leave cosmetics for last if time permits. Keep the tests green after every small behavior-preserving step; if a change forces a test edit, say why out loud (it pinned an implementation detail, not a behavior).

Trap. Starting to rewrite immediately, or "improving" tests until they pass. The round grades judgment under a clock, not typing speed.

A12. Top-k frequent IDs on an unbounded stream with bounded memory. (DeepMind coding/breadth, representative.)

Worked answer. The exact hashmap plus min-heap is O(distinct IDs) memory, which violates the bound, so go approximate: Misra-Gries heavy hitters (O(m) space, finds items with frequency above n/m) or a Count-Min Sketch feeding a k-sized heap. Articulate the tradeoff out loud: exact-but-unbounded versus bounded-but-approximate. Sketches merge by adding counters, which makes the solution trivially distributed; add decay (sliding window or exponential) if "so far" becomes "recently".

Trap. Proposing the exact solution and hoping the interviewer does not notice the memory bound. Naming the bound violation first is the signal.

A13. Classic algorithms under constraints (reverse a linked list in place; hash join versus sort-merge join). (DeepMind algorithmic coding; OpenAI SWE/RE coding, candidate-reported.)

Worked answer. Keep the classic bar sharp: clean communication and explicit complexity analysis, because at DeepMind coding often gates the ML rounds. A14. Agentic coding round: 60 minutes, an unfamiliar codebase, three tasks too big to finish by hand, and an AI coding agent. Talk through how you work. (OpenAI beta round; similar Anthropic AI-collaboration round.)

Worked answer. Orient before delegating: read the entry points, run the baseline tests, triage by value and risk, and say upfront which task may not finish. Delegate in verifiable slices: the file to change, the interface to keep, the test to pass, what not to touch; prefer slices where success is mechanically checkable, and write a failing test first when the behavior is ambiguous. Review every diff like a code review: watch for tests edited until they pass, swallowed exceptions, duplicated helpers, silent signature changes, and invented APIs. Pasting the whole brief into the agent is the anti-pattern.

Round (b): ML theory and math

The DeepMind math and theory round and the OpenAI probability threads: derive on the board, state assumptions, and say where the proof breaks. Interviewers probe whether you can reason from definitions under time pressure.

B1. Derive the Bayesian posterior for a Gaussian likelihood with Gaussian prior; compute the marginal likelihood. (DeepMind math/theory, candidate-reported.)

Worked answer. A Gaussian prior times a Gaussian likelihood is a Gaussian posterior: multiply the densities, complete the square in the exponent, and read off the result. The clean statement is in precisions (inverse variances): posterior precision equals prior precision plus data precision, and the posterior mean is the precision-weighted average of the prior mean and the data. The <dfn>marginal likelihood</dfn> (the evidence) is the normalizing integral over the parameters, and it falls out in closed form for this conjugate case. Be ready to state the bias-variance tradeoff in a Bayesian frame: the prior is the bias, the data washes it out at a rate the precisions quantify.

Trap. Deriving the posterior but freezing on the marginal likelihood: it is just the integral you normalized by. Also be ready for the documented rejection point: the Bayesian view of bias and variance.

B2. Prove the convergence rate of SGD on a strongly convex objective. (DeepMind math/theory, candidate-reported.)

Worked answer. <dfn>Strong convexity</dfn> means the function curves upward at least quadratically, which gives a lower bound on the gradient norm in terms of suboptimality: far from the optimum, gradients are large. With a 1/t (or suitably decaying) step size, the expected suboptimality shrinks as O(1/t): each step multiplies the remaining error by a contracting factor plus a noise term the decaying stepsize kills. State the assumptions explicitly: Lipschitz gradients (the gradient cannot change too fast) and bounded gradient variance (the stochastic noise is controlled). Then say where the proof breaks without strong convexity: in the general convex case you only get O(1/sqrt(t)).

Trap. Quoting O(1/t) without the assumptions, or without naming what fails when strong convexity is dropped. The assumptions are the graded part.

B3. Explain the SVD and give two places it shows up in modern deep learning. (DeepMind breadth quiz, representative.)

Worked answer. The <dfn>singular value decomposition</dfn> writes any matrix W as U Sigma V^T: geometrically a rotation, then axis-aligned scaling by the singular values, then another rotation. The Eckart-Young result: truncating to the top-r singular values gives the best rank-r approximation in both Frobenius and spectral norm, which is why the SVD is the canonical low-rank tool. Two appearances in modern deep learning: LoRA, where fine-tuning updates have low intrinsic rank so Delta W = B A cuts parameters by orders of magnitude; and conditioning and training stability, where the condition number (ratio of largest to smallest singular value) governs gradient-descent convergence and spectral-norm monitoring catches exploding attention logits. Bonus connections: PCA is the SVD of the centered data matrix, and pseudo-inverses underlie linear probes.

Trap. Reciting the factorization without the geometric read or Eckart-Young. The "two places" is the actual question; the definition is the warm-up.

B4. What is the relationship between cross-entropy, KL divergence, and perplexity, and why is cross-entropy the training loss for language models? (OpenAI RE coding/math, representative.)

Worked answer. Cross-entropy decomposes as H(p, q) = H(p) + KL(p || q): the entropy of the data plus the KL divergence from the data distribution to the model. Since H(p) is fixed by the data, minimizing cross-entropy is exactly minimizing KL(p || q). With one-hot targets the loss collapses to negative log-likelihood (maximum likelihood); paired with softmax the gradient takes the clean q-minus-p form, and cross-entropy is a proper scoring rule, so it rewards calibrated uncertainty instead of overconfidence. <dfn>Perplexity</dfn> is exp of the mean cross-entropy in nats: the effective branching factor, or how many tokens the model is choosing between on average. Two caveats: perplexity is only comparable across models sharing a tokenizer, and lower perplexity does not monotonically mean better downstream behavior, which is why post-training uses preference objectives.

Trap. Saying "perplexity measures model quality" without the tokenizer caveat, or missing the H(p,q) = H(p) + KL decomposition, which is the one-line answer.

B5. When would you choose Q-learning over policy gradients, and vice versa? (DeepMind breadth, representative.)

Worked answer. <dfn>Q-learning</dfn> is value-based and off-policy: it learns a value function from replay buffers and stale data, so it is sample-efficient. Its weaknesses are the deadly triad (function approximation plus bootstrapping plus off-policy updates can diverge), overestimation bias, and awkwardness with continuous actions. <dfn>Policy gradients</dfn> directly optimize expected return: they handle continuous and stochastic actions naturally and are more stable, but they are on-policy (data-hungry), high-variance (hence baselines and advantage estimation like GAE), and step-size sensitive (hence trust regions and PPO clipping). Language-model post-training uses policy-gradient methods (PPO and critic-free variants like GRPO) because the action space is the vocabulary and generation plus reward scoring is expensive.

Trap. Listing properties without the choice rule. The interviewer wants the decision: sample efficiency and discrete actions favor Q-learning; continuous actions and stability favor policy gradients.

B6. Backprop math from scratch. (OpenAI diagnostic checklist; DeepMind breadth.)

Worked answer. Write the forward pass, then apply the chain rule layer by layer: each layer contributes its local Jacobian times the upstream gradient. Derive the linear-layer gradient explicitly (dL/dW equals the upstream gradient transposed times the input, with the matching bias term) and one activation from scratch (ReLU: pass through where the input was positive, zero elsewhere; or sigmoid: sigma times one-minus-sigma). The pattern to demonstrate is mechanical: upstream gradient, local derivative, multiply, continue backward.

Trap. Waving at "the chain rule" instead of writing the local Jacobian times upstream gradient at least once. Write one layer fully; the rest follow the pattern.

B7. Optimization dynamics: momentum, Adam/AdamW, cosine decay, weight decay. (OpenAI and DeepMind checklists.)

Worked answer. Adam keeps per-parameter first and second moment estimates of the gradient with bias correction, so each parameter gets an adaptive step size. AdamW decouples the weight decay from the gradient-based update: plain Adam folds L2 into the gradient where the adaptive scaling distorts it, while AdamW applies the decay directly to the weights. <dfn>Cosine decay</dfn> anneals the learning rate along a cosine curve after warmup; warmup matters because early gradients are noisy and large steps diverge before the moment estimates stabilize. State it as a system: warmup, then cosine decay, with decoupled weight decay throughout.

Trap. Saying "Adam is adaptive" without the moment estimates and bias correction, or confusing AdamW with "Adam plus L2". The decoupling is the point of the W.

B8. On average, how many fair coin flips until you see two heads in a row? Walk me through it. (DeepMind breadth quiz, representative; answer 6.)

Worked answer. Set up states by progress: E_0 is the expected remaining flips with no trailing head, E_1 with one trailing head. From E_0, one flip always costs 1, then with probability half you stay at E_0 (tail) and half you move to E_1 (head): E_0 = 1 + 0.5 E_0 + 0.5 E_1. From E_1: E_1 = 1 + 0.5 times 0 (head finishes) + 0.5 E_0 (tail resets). Solve: E_1 = 1 + 0.5 E_0, substitute to get 0.5 E_0 = 1 + 0.5(1 + 0.5 E_0), which gives E_0 = 6. Contrast with HT (answer 4): overlapping self-structure makes HH harder because a tail after a head destroys the progress. Narrate the state setup explicitly rather than recalling the answer; the setup is the graded skill.

Trap. Reciting "6" without the equations, or confusing HH with HT. The Markov-state setup transfers to every waiting-time question.

B9. Probability and information theory inside coding rounds; mode-covering versus mode-seeking KL. (OpenAI RE coding, representative.)

Worked answer. Maximum likelihood minimizes KL(p || q), which is mode-covering: it penalizes assigning zero mass where the data has mass, so the model stretches to cover every mode, even at the cost of putting mass where no data lives. The reverse, KL(q || p), is mode-seeking: it penalizes the model for putting mass where data has none, so it locks onto one mode and ignores the rest. Be fluent under time pressure with expectations, conditional expectation, and basic concentration intuition: these get woven into coding rounds as follow-ups, not as standalone questions.

Trap. Mixing up the direction: the asymmetry is the whole point. Remember it as "the first argument is what you average over".

C5. PPO mechanics: why clip the importance ratio instead of using a KL penalty alone? (DeepMind RL/post-training; OpenAI RE.)

Worked answer. PPO optimizes a clipped surrogate objective: clip the probability ratio to [1-epsilon, 1+epsilon] and take the pessimistic (minimum) of the clipped and unclipped objectives times the advantage. Clipping is a first-order trust region: it bounds the update without the expensive constrained optimization of TRPO, and it is more robust than a bare KL penalty, which can be gamed or needs adaptive tuning to stay effective. The value model (critic) supplies advantage estimates, often via GAE, to reduce policy-gradient variance. The KL penalty to the reference model usually stays as an additional leash in RLHF.

Trap. Saying clipping "stabilizes training" without the trust-region argument. The question is why clipping beats the KL penalty alone: no adaptive coefficient to tune, and the bound holds per update.

C6. DPO and IPO as alternatives to PPO; online training and distillation. (OpenAI RE; DeepMind.)

Worked answer. <dfn>DPO</dfn> (Direct Preference Optimization) reparameterizes the RLHF objective so the optimal policy is found by direct classification on preference pairs: no separate reward model, no RL loop. <dfn>IPO</dfn> is a variant that avoids DPO's tendency to overfit the preference data. The tradeoff: simpler and more stable than PPO, but offline (no exploration beyond the preference data) and still needs the KL-to-reference regularization. Online variants collect fresh preference data from the current policy to fix the staleness; <dfn>distillation</dfn> transfers a large model's behavior into a smaller one for serving cost.

Cross-cutting signals

Six signals from the guides that apply in every round, worth internalizing before any loop:

  • Train unaided. DeepMind and Anthropic prohibit AI tools in technical rounds; OpenAI varies by track, with research and infrastructure rounds generally AI-prohibited. From-scratch ML coding where the code must run is the norm at DeepMind.
  • Staged problems reward clean code. Progressive-spec problems dominate Anthropic and OpenAI coding: the interviewer adds requirements and edge cases. Clean modular code that absorbs change beats pre-optimized code.
  • Tradeoffs three levels deep. Every system design answer is graded on tradeoff reasoning; name-dropping a technology you cannot defend is a known failure mode at OpenAI.
  • Evals are an engineering discipline. Every design answer should include how you would measure it; contamination awareness is explicitly tested at DeepMind.
  • Write tests unasked. Test coverage is an explicit grading axis at OpenAI, unusual among the labs.
  • The values round is real. It is a hard gate at Anthropic (mission mismatch is the most documented rejection cause) and a real round at OpenAI and DeepMind; prepare it like a technical round.

Key takeaways

  • Practice every coding round without AI assistance, with the code running.
  • Build the habit: every design answer ends with tradeoffs and a measurement plan.
  • Write tests even when not asked; at OpenAI it is graded.
  • Prepare values answers with the same rigor as technical answers.
