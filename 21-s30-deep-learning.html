Why this category exists

Volume 19 fitted models whose gradients had closed forms. Deep learning removes that comfort: the model is a long chain of nonlinear layers, the loss surface is non-convex, and everything about training is a procedure you must run correctly. The three questions of this volume are: how do gradients flow through a network, how do you keep that flow healthy, and how do you steer it to a good solution. The labs answer by making you build each piece from scratch in NumPy before you ever trust a framework.

Without these skills, four things fail. First, you cannot debug training: loss explodes or flatlines and you have no mental model of why. Second, deep networks silently stop learning when activations saturate or gradients vanish, and the symptoms look like a data problem. Third, a bad optimizer setup wastes weeks of GPU time on a model that was fine. Fourth, you re-derive from scratch what the field already knows: convolutions for images, augmentation for data efficiency, transfer learning for small datasets.

The category opens with three data-engineering labs (days 6.1 to 6.3: preprocessing pipelines, multi-table joins, silver tables) because deep learning is fed by data plumbing, and the most common real-world ML task is building correct features from event logs. Concept 1: backprop is the chain rule, mechanized

A computation graph is the network drawn as operations: each node takes inputs, computes an output, and remembers what it needs for the backward pass. The forward pass evaluates the graph and caches intermediate values. The backward pass walks the graph in reverse, applying the chain rule (the derivative of a composition is the product of the derivatives) to compute the gradient of the loss with respect to every parameter. Finite differences approximate a derivative numerically as (f(x + h) - f(x - h)) / (2h) and serve as the ground truth that checks your backward pass.

This exists because Volume 3 derived backprop once, but derivations do not become instincts until you implement them. Every training run in the rest of this volume depends on gradients being exactly right; a sign error or a forgotten cache entry corrupts every update silently. The lab builds the classic Value object: a scalar that carries its data, its gradient, its parents, and a backward closure. Softplus is implemented with Value ops as the exercise.

The mechanics on the diagram: forward, x = 2 and y = 3 multiply to t = 6, then z = 4 adds to give v = 10. Backward, seed dv/dv = 1 at the output. Through the add node, the gradient passes unchanged: dv/dt = 1 and dv/dz = 1. Through the multiply node, each input gets the upstream gradient times the other input: dv/dx = 1 * 3 = 3, dv/dy = 1 * 2 = 2. The general rule at each node: multiply the incoming gradient by the local derivative.

Concrete check: implement f(x) = x^3 at x = 2 with h = 1e-5. Finite differences give ((2.00001)^3 - (1.99999)^3) / (2e-5) = 12.0000000002, matching the analytic 3x^2 = 12. If your Value backward disagrees past the sixth decimal, the backward closure is wrong, not the check.

The misunderstanding: "autograd handles it, so I do not need to understand it." Autograd handles the bookkeeping, but every debugging session in this volume, vanishing gradients, exploding updates, dead neurons, is a question about what the backward pass computed. If you cannot do it on a three-node graph, you cannot read a training curve.

How to read this diagram

  1. Each box or circle is an operation; edges carry values forward and gradients backward.

  4. Through the addition, gradients pass through unchanged: dv/dt = 1, dv/dz = 1.
  5. Through the multiplication, each input receives the upstream gradient times its sibling: dx = 3, dy = 2.

  • Through an add, gradients pass unchanged; through a multiply, each input gets upstream times its sibling.
  • Finite differences are the ground truth for checking any backward implementation.
  • If you cannot backprop a three-node graph by hand, training curves are unreadable.

Concept 2: activations and initialization keep the signal alive

An activation function is the nonlinearity applied after each affine transform; without it, stacked layers collapse into one linear map. The three you must know: ReLU (rectified linear unit), max(0, x); tanh (hyperbolic tangent), squashing to [-1, 1]; GELU (Gaussian error linear unit), a smooth ReLU-like curve used in transformers. Initialization is the distribution the weights are drawn from before training. Dying ReLU is a neuron stuck outputting zero forever because its inputs never push it positive. The vanishing gradient is gradients shrinking toward zero as they travel back through many layers, so early layers stop learning.

This exists because a network is a repeated multiplication of signals and gradients. If each layer shrinks the variance a little, twenty layers shrink it to nothing; if each layer grows it a little, activations explode. The labs make you simulate this: a forward-stats simulator reports mean and variance of activations per layer for each init and activation pair. Tanh with unit-variance init saturates: activations pile up near -1 and 1 where the derivative is near zero, and gradients die. ReLU with the same init is better but still drifts; He initialization draws weights with variance 2 / fan-in to compensate exactly for ReLU zeroing half the signal. Xavier initialization uses variance 1 / fan-in and pairs with tanh and sigmoid.

Mechanics of the failure: tanh derivative is 1 - tanh(x)^2, which is near zero when |x| is large. Each backward step multiplies by a number below 1, so after L layers the gradient is scaled by a product of L small numbers: exponential decay. He init keeps the forward variance near 1 per layer, so inputs stay in the region where derivatives are healthy.

Concrete numbers from the simulation pattern: 20-layer tanh network with standard-normal init. Activation standard deviation by layer: 1.0, 0.9, 0.7, 0.5, 0.3, then effectively 0 by layer 10, while the mean drifts toward saturation. Gradient norms at each layer decay by roughly 0.6x per layer going backward. The same depth with He init and ReLU holds activation std near 1.0 across all 20 layers.

The misunderstanding: "initialization is a minor detail; the optimizer will fix it." The optimizer multiplies the gradient it is given. A dead gradient gives it nothing to multiply, and no learning rate repairs a signal that is exactly zero.

  3. The red curve (std-1 init plus tanh) decays toward zero while activations saturate at the extremes.

Key takeaways

  • Stacked linear layers without activation collapse to one linear map; the activation is what buys depth.
  • He init (variance 2/fan-in) pairs with ReLU; Xavier init (variance 1/fan-in) pairs with tanh.
  • Tanh saturates and kills gradients; ReLU can die but does not saturate on the positive side.
  • Simulate forward statistics before training deep nets; do not guess.

Concept 3: optimization is steering, not just descending

SGD (stochastic gradient descent) updates weights with the gradient of one mini-batch: w = w - lr * g. Momentum keeps a running average of past gradients and steps along it, which damps zigzagging in narrow valleys. Adam (adaptive moment estimation) tracks both a moving average of gradients and of squared gradients, giving each parameter its own effective learning rate. AdamW decouples weight decay from the adaptive update, which Adam otherwise applies unevenly. A learning rate schedule changes the learning rate during training; warmup ramps it from near zero to avoid early instability, and cosine decay anneals it smoothly to zero. Gradient clipping rescales any gradient whose norm exceeds a cap, keeping the direction but bounding the step.

Plain SGD exists as the baseline everything else is measured against. Momentum exists because ravines in the loss surface make raw gradients oscillate across the valley while crawling along it. Adam exists because different parameters live on different scales; per-parameter rates converge faster in practice, though they can generalize slightly worse than well-tuned SGD. Schedules exist because the right step size early (large, exploratory) is not the right step size late (small, refining). Clipping exists because one bad batch, or one RNN step, can produce a gradient norm of 12 where 1 is normal, and a single unclipped step can undo hours of training.

Clipping mechanics: compute the global norm ||g|| over all parameters. If ||g|| exceeds the cap c, replace g with g * (c / ||g||). The direction is identical; only the magnitude is bounded. The quadratic experiment in the lab: f(x) = 0.5 x^T A x with condition number 100. Plain gradient descent zigzags across the steep direction and crawls along the flat one; momentum cuts through the zigzag; Adam adapts per-axis.

Concrete numbers: a gradient with norm 12.0 and cap 1.0 is scaled by 1/12, so each component shrinks twelvefold but points the same way. In the LR-schedule comparison, constant learning rate oscillates around the minimum while warmup plus cosine decay settles into it; without clipping, one spike batch at step 400 throws the loss back to its initial value.

The misunderstanding: "Adam is always better than SGD." The w7-d2 lab has you compare Adam vs AdamW weight norms directly: AdamW keeps weight norms smaller and more stable, and on several classic setups tuned SGD with momentum matches or beats Adam on final validation. The honest answer is that the optimizer is a hyperparameter, not a religion.

How to read this diagram

  1. Left panel: one bad batch produces a gradient of norm 12; the raw step jumps far.
  2. That single step can undo hundreds of steps of progress; the loss explodes.
  3. Right panel: the same gradient is rescaled by 1/12, so its norm becomes exactly 1.0.
  4. The direction is unchanged; only the magnitude is bounded.
  5. This is why clipping is standard in RNN and transformer training, where spikes are routine.
  6. The lab shows the spike live: large learning rate without clipping versus with.

Interview relevance. "When would you use SGD with momentum over Adam?" and "what does gradient clipping do to the update direction?" are both direct hits from the w7-d2 lab material.

Key takeaways

  • Momentum damps oscillation; Adam adapts per-parameter rates; AdamW decouples weight decay properly.
  • Warmup plus cosine decay is the default schedule worth knowing by heart.
  • Clipping bounds the step norm without changing its direction; it is cheap insurance against spikes.
  • Compare optimizers on validation, not on training speed; faster is not better.

Concept 4: convolutions, residuals, augmentation, and transfer

A convolution slides a small filter across the input, computing dot products at each position; weight sharing means the same filter is reused everywhere, which gives translation equivariance (a shifted input gives a shifted feature map) and far fewer parameters than a dense layer. Max-pooling downsamples by taking the maximum over each small window, building in local invariance. A residual connection adds the input of a block to its output, y = F(x) + x, giving gradients a skip path straight through. Data augmentation applies label-preserving transforms (shifts, noise, cutout) to manufacture training variety. Mixup and cutmix blend two images and their labels into soft targets. Transfer learning reuses a network trained on a large task: freeze the early layers as a feature extractor and train only a new head, or fine-tune everything gently.

Convolutions exist because images have local structure and translation symmetry; a dense layer would learn the same edge detector separately at every position. Pooling exists to shrink the spatial grid and add robustness to small shifts. Residuals exist because plain stacks hit the vanishing gradient from Concept 2 at depth: the w7-d5 lab simulates gradient norms per layer and shows them decaying in a plain stack and staying flat with skip connections, because the identity path carries the gradient through untouched. Augmentation exists because labeled images are expensive and models memorize; mixup and cutmix further regularize by forcing linear behavior between examples. Transfer exists because early convolutional filters (edges, textures) are universal: training them from scratch on a small dataset wastes data.

Shape mechanics: for a convolution with input width W, kernel K, stride S, padding P, the output width is (W - K + 2P) / S + 1. With W = 28, K = 3, S = 1, P = 1, the output is 28: same size, which is why stacks of 3x3 convolutions are the default building block. Max-pool 2x2 with stride 2 halves each spatial dimension.

Concrete numbers from the transfer lab: a small target set where training from scratch reaches 71 percent, while frozen pretrained features plus a new head reach 84 percent, and frozen random features reach only 63 percent. The gap between 84 and 63 is the value of the transferred representation; the gap between 84 and 71 is what you gain by not wasting your small dataset on learning edges. For augmentation, baseline 78 percent, plus shift/noise/cutout 83 percent, plus mixup 84.5 percent.

The misunderstanding: "augmentation always helps." A transform that breaks the label, like flipping digits where 6 becomes 9, or cropping out the object, teaches the model the wrong invariance. Augmentation must preserve what the label means. The second misunderstanding: "deeper is always better." Without residuals, deeper is worse; the lab proves it with the gradient-norm simulation.

Key takeaways

  • Convolutions exploit locality and translation symmetry; pooling builds shift robustness.
  • Residual connections fix the vanishing gradient by giving it an identity skip path.
  • Augmentation must preserve label semantics; mixup and cutmix regularize with soft targets.
  • Transfer learning: frozen features plus a new head beats from-scratch on small data; random frozen features do not.

def sgd_step(w, g, lr):
    return w - lr * g

def momentum_init(w):
    return {'v': np.zeros_like(w)}

def momentum_step(w, g, state, lr, beta=0.9):
    state['v'] = beta * state['v'] + (1 - beta) * g
    return w - lr * state['v'], state

def adam_init(w):
    return {'m': np.zeros_like(w), 'v': np.zeros_like(w), 't': 0}

def adam_step(w, g, state, lr, b1=0.9, b2=0.999, eps=1e-8):
    state['t'] += 1
    t = state['t']
    state['m'] = b1 * state['m'] + (1 - b1) * g
    state['v'] = b2 * state['v'] + (1 - b2) * (g * g)
    mhat = state['m'] / (1 - b1**t)
    vhat = state['v'] / (1 - b2**t)
    w = w - lr * mhat / (np.sqrt(vhat) + eps)
    return w, state

def maxpool2d_forward(x, pool=2, stride=2):
    N, C, H, W = x.shape
    H_out = (H - pool) // stride + 1
    W_out = (W - pool) // stride + 1
    out = np.zeros((N, C, H_out, W_out), dtype=float)
    for n in range(N):
        for c in range(C):
            for i in range(H_out):
                hs = i * stride
                for j in range(W_out):
                    ws = j * stride
                    patch = x[n, c, hs:hs+pool, ws:ws+pool]
                    out[n, c, i, j] = float(np.max(patch))
    return out

Task 2 Implement `simulate_grad_norms(depth, d, mode)` returning an array of gradient norms at each layer. Gradient flow simulation (why ResNets help)

Section 1 , Gradient flow simulation (why ResNets help)

We simulate backprop gradient norm through a deep network with random linear layers.

Key idea:

  • Plain: h_{l+1} = W_l h_l
  • Residual: h_{l+1} = h_l + W_l h_l

In backward, the Jacobians multiply. Residual blocks add an identity term that prevents norms from collapsing too fast.

Important: the returned array is ordered from input side -> loss side. So if early-layer gradients vanish, the first value should be much smaller than the last value.

def mixup_batch(Xb_flat, yb, K, r, alpha=0.4):
    B = Xb_flat.shape[0]
    perm = r.permutation(B)
    lam = float(r.beta(alpha, alpha))
    X2 = Xb_flat[perm]
    y1 = onehot(yb, K)
    y2 = onehot(yb[perm], K)
    Xm = lam * Xb_flat + (1.0 - lam) * X2
    ym = lam * y1 + (1.0 - lam) * y2
    return Xm, ym

Q1. In v = x*y + z with x=2, y=3, z=4, you seed dv/dv = 1. What are dv/dx, dv/dy, dv/dz?

Answer: dv/dx = 3, dv/dy = 2, dv/dz = 1.

  • 3 / 2 / 1, right: through the multiply, each input gets upstream times its sibling (1*3, 1*2); through the add, the gradient passes unchanged.
  • 2 / 3 / 1, wrong: this assigns each input its own value instead of its sibling; the chain rule crosses them.
  • 6 / 6 / 1, wrong: this multiplies by the product instead of the sibling; only one factor crosses at a time.

Q2. Which initialization pairs with ReLU, and what goes wrong if you use unit-variance init with tanh in a 20-layer net?

Answer: He init (variance 2/fan-in) for ReLU. Unit-variance init with tanh saturates activations, derivatives go to zero, and gradients vanish.

  • He + saturation argument, right: the 2 compensates for ReLU zeroing half the signal; tanh saturation kills the backward product.
  • Xavier for ReLU, wrong: Xavier assumes a symmetric activation; with ReLU the variance halves each layer and the signal still decays.
  • Nothing, the optimizer adapts, wrong: the optimizer scales the gradient it receives; a vanished gradient gives it nothing to work with.

Q3. A training run diverges after one batch with gradient norm 50. Your colleague suggests lowering the learning rate 10x. You suggest clipping at 1.0. Who is right, and what is the tradeoff?

Answer: clipping is the better first move: it bounds only the spike while keeping the learning rate (and progress) on normal batches; lowering the rate 10x slows the entire run.

  • Clip first, right: spikes are outliers; clipping treats them as outliers instead of penalizing every step.
  • Lower the rate, wrong as first move: it works but costs 10x the steps everywhere, including the 99 percent of batches that were fine.
  • Both are equivalent, wrong: clipping preserves direction and only caps magnitude; a global rate cut changes every update.
