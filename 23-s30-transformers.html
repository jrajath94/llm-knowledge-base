Why this category exists

Nearly every product in modern AI is a transformer with text plumbing around it. The model behind chatbots, code assistants, search copilots, and the retrieval systems of Volume 24 is the same architecture you build by hand in these labs. That ubiquity is exactly why the category exists: a research engineer cannot treat the transformer as a black box. You need to know what breaks inside it, what its costs are, and how to change its behavior.

Without these skills, four failures are routine. First, attention looks like magic, so debugging a model that ignores context becomes guesswork. Second, training collapses for no visible reason: loss spikes, gradients explode, and the fix is a scheduler or a clipping threshold you never learned. Third, tokenizers produce surprises: your prompt costs twice what you expected because the tokenizer split words you assumed were whole. Fourth, inference costs explode: a naive decode loop recomputes everything per token and turns a demo into a bill. Each failure has a lab here that makes it concrete.

Core ideas, worked end to end

1. Self-attention and the scaled dot-product

What it is, in plain words. Self-attention is a mechanism that lets every token in a sequence build its representation by taking a weighted mix of all tokens' representations, including itself. Scaled dot-product attention is the concrete formula: Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V, where the queries (Q), keys (K), and values (V) are three different linear projections of the same input. Think of keys as labels on filing folders, the query as what you are looking for, and values as the folder contents.

Why it exists. Before attention, sequence models were recurrent neural networks (RNNs): they processed tokens one at a time and squeezed the entire history into a fixed-size hidden state. Long-range dependencies faded because gradients had to travel back through every step (backpropagation through time, BPTT), which is exactly what the Week 9 Day 2 lab makes you feel by training a vanilla RNN and watching gradient clipping kick in. Attention replaces the single bottleneck with direct pairwise connections: every token talks to every other token in one step, an O(1) path instead of an O(n) chain.

How it works, step by step. (1) Project the input X (n tokens by d features) into Q, K, V with three learned matrices. (2) Compute the score matrix S = Q K^T, an n by n table where entry (i, j) says how much token i wants to look at token j. (3) Scale by 1 / sqrt(d_k), where d_k is the key dimension. (4) Apply the softmax (exponentiate and normalize) to each row so the weights sum to one; in a causal language model, first add the causal mask, which sets all future positions to negative infinity so a token cannot peek ahead. (5) Multiply the weights A by V: each output row is a weighted sum of value vectors. Multi-head attention runs this whole procedure h times in parallel with different projections and concatenates the results, so each head can track a different kind of relationship.

Worked example. Three tokens, d_k = 2, token A's query q = [1, 0], keys k1 = [1, 0], k2 = [0, 1], k3 = [-1, 0]. Raw scores are the dot products: [1, 0, -1]. Divide by sqrt(2) = 1.414 to get [0.707, 0, -0.707]. Softmax: exp gives [2.028, 1.000, 0.493], which normalize to [0.576, 0.284, 0.140]. Token A therefore mixes 57.6 percent of token 1's value, 28.4 percent of token 2's, and 14.0 percent of token 3's. With 8 heads and d_model = 512, each head works in d_k = 64 dimensions.

The misunderstanding interviewers exploit. Attention weights are not explanations. A high weight means the model routed information through that token, not that the token caused the prediction. The second trap is the mask: you must mask future positions before the softmax, not after. Masking after softmax leaves the leaked probability mass inside the denominator and silently trains a model that has seen the future. The Day 3 tiny-LM lab lists exactly this as its first gotcha.

Key takeaways

  • Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V; causal models mask the future before the softmax.
  • It replaced RNNs because every token pair gets a direct O(1) connection instead of a fading recurrent chain.
  • Multi-head attention runs h parallel attention layers in subspaces so heads specialize.

2. The transformer block: residuals, normalization, and where position comes from

What it is, in plain words. A transformer block is one repeated unit of the architecture. In the pre-norm layout the labs use, each block computes y = x + MHA(LayerNorm(x)) and then z = y + FFN(LayerNorm(y)). A residual connection (the "x +" part) adds the input back to the sublayer output. Layer normalization (LayerNorm) rescales each token's vector to zero mean and unit variance. The feed-forward network (FFN) is a two-layer MLP, usually expanding from d to 4d and back, with a GELU (Gaussian error linear unit) nonlinearity in the middle.

Why it exists. Attention by itself is permutation-equivariant: shuffle the input tokens and the outputs shuffle identically, so the model has no notion of order. That is why position must be injected explicitly, and it is why positional encodings exist. Depth is the other problem: stacking dozens of attention and FFN layers makes gradients vanish, exactly the failure the deep-learning volumes diagnose. Residuals give every gradient a clean identity path around each sublayer, and normalization keeps activations in a range the next layer can use. Without both, a 12-block model simply does not train.

How it works, step by step. (1) Embed each token id by looking up its row in the embedding matrix, then add the positional encoding. The sinusoidal positional encoding used in the lab is PE(pos, 2i) = sin(pos / 10000^(2i/d)), PE(pos, 2i+1) = cos(pos / 10000^(2i/d)): each position gets a unique smooth pattern across dimensions. (2) Normalize, run multi-head attention, add the residual. (3) Normalize again, run the FFN, add the residual. (4) Repeat for all blocks, then a final normalization and an output projection to vocabulary logits. The Day 1 Week 10 lab implements every piece: utilities (softmax, LayerNorm, GELU), positional encoding, embedding lookup, masks, head split and merge, attention over heads, the FFN, and the full block forward.

Worked example. Take d_model = 512, 8 heads, d_ff = 2048. Attention holds four 512 by 512 matrices (W_q, W_k, W_v, W_o): 4 x 262,144 = about 1.0M parameters. The FFN holds 512 x 2048 and 2048 x 512: about 2.1M parameters, twice the attention. One block is roughly 3.1M parameters, so a 12-block model is about 37M. Two lessons fall out: the FFN, not attention, holds most of the capacity, and a "small" transformer is mostly matrix multiplies, which is why these models love GPUs.

The misunderstanding interviewers exploit. Candidates call the FFN "just a classifier on top" or treat residuals as a minor trick. The FFN layers are where the model stores most of what it knows (one useful mental model: the first FFN matrix as keys, the second as values, a giant associative memory). And residuals are not a trick at all; they are the reason 100-layer networks train. The follow-up trap is pre-norm versus post-norm: the original transformer normalized after the residual, modern models normalize before, and you should know which one the lab used and why pre-norm trains more stably at depth.

  • Attention has no order; sinusoidal positional encodings inject it before the first block.
  • The FFN holds roughly twice the parameters of attention and most of the stored knowledge.

3. Tokenization and embeddings: text becomes numbers, numbers become meaning

What it is, in plain words. A tokenizer converts raw text into a sequence of integer ids; an embedding converts each id into a dense vector the model can compute with. Modern tokenizers use byte-pair encoding (BPE): start from single characters, repeatedly merge the most frequent adjacent pair, and keep merging until the vocabulary reaches its target size. The result is subword tokens: frequent strings like "the" stay whole, rare words split into pieces. Word embeddings assign each token a vector such that similar meanings sit near each other; the lab builds them two ways, PPMI (positive pointwise mutual information) with SVD (singular value decomposition), and SGNS (skip-gram with negative sampling), then compares their behavior on analogy tasks.

Why it exists. Word-level vocabularies explode: every new word needs a new id, and unseen words break the model (out-of-vocabulary, OOV). Character-level sequences keep the vocabulary tiny but make sequences so long that attention's quadratic cost hurts. Subwords are the compromise: a bounded vocabulary (tens of thousands) with almost no OOV, because anything unseen decomposes into known pieces. Embeddings exist because integers carry no meaning: id 412 and id 413 are no more related than 412 and 8901, so each id needs a learned vector where geometry encodes semantics.

How it works, step by step. (1) Normalize the corpus: lowercase, handle punctuation and whitespace consistently. (2) Learn BPE merges: count all adjacent symbol pairs in the corpus, merge the most frequent pair into a new symbol, repeat for a fixed number of merges. (3) Encode new text greedily with the learned merges. (4) Map tokens to ids; reserve id 0 for UNK, as the lab does. (5) Train embeddings: PPMI builds a word-by-context co-occurrence matrix, keeps only positive associations, and factorizes it with SVD to get dense vectors; SGNS trains a tiny classifier to predict context words while contrasting against randomly sampled negative samples, which is cheaper on large corpora. The Day 3 tokenization lab also implements WordPiece-style and unigram-style segmentation and compares all three.

Worked example. "unbelievable" encodes as ["un", "believ", "able"] with ids like [412, 8901, 233]. A 50k BPE vocabulary gives English text a fertility (tokens per word) of roughly 1.3, so a 1,000-word prompt is about 1,300 tokens: the number your inference bill actually counts. On analogies, both PPMI+SVD and SGNS vectors solve "king - man + woman" nearest to "queen" via cosine similarity (the angle between vectors, ignoring length), but the lab's comparison task shows they differ on rarer relations, which is the honest empirical point: no embedding method wins everywhere.

The misunderstanding interviewers exploit. "Tokens are words." They are not: a leading space changes the token (" hello" versus "hello" are different ids), numbers split in surprising places, and non-English text can have far worse fertility, which quietly doubles costs. The deeper trap: changing the tokenizer after training is not allowed. The embedding matrix is indexed by tokenizer ids; a new tokenizer means a new matrix and a model that has forgotten what every row means.

How to read this diagram

  1. Raw text enters at top left. Normalization (lowercasing, punctuation handling) runs first and must match training exactly.
  2. BPE merges learned on the corpus split "unbelievable" into the subwords "un", "believ", "able"; frequent strings stay whole, rare ones split.
  3. Subwords become integer ids; anything unseen maps to UNK, which the lab reserves as id 0.
  4. Each id indexes a row of the embedding matrix (vocab by d), producing the dense vectors that enter the first transformer block.

  • The model never sees text, only ids; each id indexes a learned embedding row where geometry encodes meaning.
  • Fertility (tokens per word) is what you pay for; tokenizer and model are a married pair, never swapped after training.

4. Attention economics and training stability: the two cost centers

What it is, in plain words. Two separate bills dominate transformer work. The inference bill is attention economics: prefill (processing the prompt once) costs O(n^2 d), and naive decoding (generating one token at a time) would repeat that work per token. The KV cache fixes it by storing every layer's keys and values so each new token only computes its own row. FlashAttention is a tiled algorithm that computes exact attention without ever materializing the n by n score matrix, by streaming blocks through fast on-chip memory with an online softmax. The training bill is training stability: the bag of tricks (learning-rate warmup, cosine decay, gradient clipping, AdamW) that keeps large runs from diverging.

Why it exists. Without the KV cache, generating token 4,000 recomputes keys and values for tokens 1 through 3,999 at every layer: O(n) fresh work per step becomes O(n^2) per step, and long generations crawl. Without tiling, the score matrix itself does not fit in memory at long contexts. Without the stability kit, the same run that trains fine at small scale explodes at large scale: early steps take oversized jumps (fixed by warmup), late steps oscillate (fixed by decay), one bad batch sends gradients to infinity (fixed by clipping), and coupled weight decay interacts badly with adaptive step sizes (fixed by AdamW, which decouples them).

How it works, step by step. Inference: (1) Prefill runs the full forward pass over the prompt and saves K and V per layer. (2) Each decode step computes only the new token's q, k, v, appends k and v to the cache, and attends over the cached history: O(n d) work per step instead of O(n^2 d). (3) FlashAttention goes further inside the computation: it never writes the n by n matrix, tiling Q, K, V blocks through SRAM and tracking softmax statistics incrementally; the output is bit-identical to naive attention. Training: (1) Warm up the learning rate linearly over the first few thousand steps, then decay with a cosine schedule to a small floor. (2) After backprop, compute the global gradient norm and rescale gradients if it exceeds a threshold. (3) Use AdamW so weight decay is a clean additive term, not folded into the adaptive denominator. (4) Compute softmax as exp(x - max(x)) / sum(exp(x - max(x))) so large logits cannot overflow. The fine-tuning lab adds the adaptation side: compare full fine-tuning against head-only and frozen-extractor strategies on a second task, keeping validation splits fixed so the comparison is honest.

Worked example. A 32-layer, 32-head model with d_head = 128, context n = 4096, fp16: the KV cache holds 2 x 32 x 32 x 128 x 4096 x 2 bytes = 2.1 GB per sequence. The full score matrix, if materialized, would be 4096^2 x 32 heads x 32 layers x 2 bytes = 34 GB, which is why tiling is not optional at long context. On the training side, a typical recipe from the lab: warm up to a peak learning rate around 3e-4 over the first 2,000 steps, cosine-decay toward 3e-5, clip the global norm at 1.0, and watch AdamW keep weight norms lower and steadier than Adam on the same run.

The misunderstanding interviewers exploit. "The KV cache makes generation free." It does not: decoding becomes memory-bandwidth bound, and the cache itself (2.1 GB in the example) caps how many sequences fit on a GPU. "FlashAttention is an approximation." It is exact; the savings are memory traffic, not math. On training: "warmup is just being careful" misses the mechanism, which is that adaptive optimizers take their largest, least-informed steps at initialization, exactly when the landscape is most treacherous.

How to read this diagram

  1. Prefill (blue) processes the whole prompt at O(n^2 d) cost and fills the KV cache once.
  2. The cache (amber) stores keys and values for every layer, head, and position: 2 x layers x heads x d_head x n numbers.
  3. Decode (green) generates one token at a time, reusing the cache for O(n d) work per step.
  4. The memory check shows the stakes at n = 4096: a 2.1 GB cache versus a 34 GB score matrix you must never materialize; FlashAttention tiles through SRAM instead.
  5. The bottom panel is the training stability kit: warmup plus cosine schedule, gradient clipping, AdamW, and the stable softmax formulation.

Interview relevance. "How much KV cache does this model need at this context length?" is a capacity-planning question that separates people who have done the arithmetic from people who have only read about it. Pair it with "why warm up the learning rate?" for the training half.

Key takeaways

  • KV cache turns per-token decode from O(n^2 d) into O(n d); its size, not compute, often caps serving.
  • FlashAttention is exact: it tiles Q, K, V through fast memory so the n by n matrix never exists.
  • Warmup plus cosine decay, gradient clipping, and AdamW are the standard defense against divergence at scale.

def build_cooccurrence(texts: list[str], word2id: dict[str,int], window: int = 2) -> np.ndarray:
    V = len(word2id)
    C = np.zeros((V, V), dtype=np.float64)
    for s in texts:
        ids = [word_id(w, word2id) for w in tokenize(s)]
        for i, center in enumerate(ids):
            lo = max(0, i - window)
            hi = min(len(ids), i + window + 1)
            for j in range(lo, hi):
                if j == i:
                    continue
                C[center, ids[j]] += 1.0
    return C

Section 2 , PMI / PPMI

PMI stands for Pointwise Mutual Information.

PMI(i,j) = log( P(i,j) / (P(i) P(j)) ). PPMI(i,j) = max(PMI(i,j), 0).

Intuition: PMI measures how much more often two words occur together than chance would predict. If a pair appears together more than expected, PMI is positive. If it appears less than expected, PMI is negative. PPMI keeps only the positive values, which is the core idea behind PPMI.

def ppmi(C: np.ndarray, eps: float = 1e-12) -> np.ndarray:
    total = C.sum()
    row = C.sum(axis=1, keepdims=True)
    col = C.sum(axis=0, keepdims=True)
    Pij = C / max(total, eps)
    Pi = row / max(total, eps)
    Pj = col / max(total, eps)
    pmi = np.log((Pij + eps) / (Pi @ Pj + eps))
    return np.maximum(pmi, 0.0)

M = ppmi(C)
check('nonneg', float(M.min()) >= 0.0)

def neg_sampling_cdf(counts: Counter, word2id: dict[str,int], power: float = 0.75) -> np.ndarray:
    V = len(word2id)
    w = np.zeros((V,), dtype=np.float64)
    for word, idx in word2id.items():
        c = counts.get(word, 0)
        if idx == 0:
            c = 0
        w[idx] = float(c) ** power
    if w.sum() <= 0:
        w = np.ones_like(w)
        w[0] = 0
    p = w / w.sum()
    return np.cumsum(p)

def sample_neg(cdf: np.ndarray, n: int, rng: np.random.Generator) -> np.ndarray:

    n, d = X.shape
    W = 0.01 * rng.standard_normal((d, k))
    b = np.zeros((k,), dtype=np.float64)
    Y = np.eye(k)[y]
    for _ in range(steps):
        P = softmax(X @ W + b)
        gradW = (X.T @ (P - Y)) / n + l2 * W
        gradb = (P - Y).mean(axis=0)
        W -= lr * gradW
        b -= lr * gradb
    return W, b

    return np.argmax(X @ W + b, axis=1).astype(np.int64)

def scaled_dot_attn(Q: np.ndarray, K: np.ndarray, V: np.ndarray, mask = None):

def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    m = np.max(x, axis=axis, keepdims=True)
    z = x - m
    e = np.exp(z)
    return e / np.sum(e, axis=axis, keepdims=True)

def layer_norm(x: np.ndarray, gamma: np.ndarray, beta: np.ndarray, eps: float = 1e-5) -> np.ndarray:
    mu = np.mean(x, axis=-1, keepdims=True)
    var = np.mean((x - mu) ** 2, axis=-1, keepdims=True)
    xhat = (x - mu) / np.sqrt(var + eps)
    return xhat * gamma + beta

def gelu(x: np.ndarray) -> np.ndarray:
    return 0.5 * x * (1.0 + np.tanh(np.sqrt(2.0 / np.pi) * (x + 0.044715 * (x ** 3))))

def attn_heads(Q: np.ndarray, K: np.ndarray, V: np.ndarray, mask=None):

def lr_warmup_cosine(step: int, base_lr: float, warmup_steps: int, total_steps: int, min_lr: float) -> float:
    if total_steps <= 0:
        raise ValueError('total_steps must be positive')
    if warmup_steps > 0 and step < warmup_steps:
        return float(base_lr * (step + 1) / warmup_steps)
    if total_steps <= warmup_steps:
        return float(base_lr)
    span = max(1, total_steps - warmup_steps - 1)
    progress = min(max((step - warmup_steps) / span, 0.0), 1.0)
    cosine = 0.5 * (1.0 + np.cos(np.pi * progress))
    return float(min_lr + (base_lr - min_lr) * cosine)

def global_grad_norm(grads: dict) -> float:
    sq = 0.0
    for g in grads.values():
        sq += float(np.sum(g * g))
    return float(np.sqrt(sq))

def clip_global_norm(grads: dict, max_norm: float):
    raw_norm = global_grad_norm(grads)
    if raw_norm == 0.0 or raw_norm <= max_norm:
        return {k: v.copy() for k, v in grads.items()}, raw_norm, 1.0
    scale = float(max_norm / (raw_norm + 1e-12))
    clipped = {k: scale * v for k, v in grads.items()}
    return clipped, raw_norm, scale

def get_batch(data: np.ndarray, batch_size: int, T: int, seed: int = 0):
    rng = np.random.default_rng(seed)
    n = data.size

def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    m = np.max(x, axis=axis, keepdims=True)
    z = x - m
    e = np.exp(z)
    return e / np.sum(e, axis=axis, keepdims=True)

def log_softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    m = np.max(x, axis=axis, keepdims=True)
    z = x - m
    return z - np.log(np.sum(np.exp(z), axis=axis, keepdims=True))

def causal_mask(T: int) -> np.ndarray:
    return np.tril(np.ones((T, T), dtype=np.int64))[None, :, :]

def xent_loss_and_grad_logits(logits: np.ndarray, Y: np.ndarray):
    B, T, V = logits.shape
    flat_logits = logits.reshape(B * T, V)
    flat_y = Y.reshape(B * T)
    ls = log_softmax(flat_logits, axis=1)
    loss = -np.mean(ls[np.arange(B * T), flat_y])
    P = np.exp(ls)
    d = P
    d[np.arange(B * T), flat_y] -= 1.0
    d /= (B * T)
    return float(loss), d.reshape(B, T, V)

def minibatches(X, y, batch_size: int, seed: int):
    rng = np.random.default_rng(seed)
    n = X.shape[0]
    perm = rng.permutation(n)
    for i in range(0, n, batch_size):
        idx = perm[i:i+batch_size]
        yield X[idx], y[idx]

def train_epoch(params, X, y, lr: float, batch_size: int, seed: int, freeze_feats: bool):
    losses = []
    accs = []
    for Xb, yb in minibatches(X, y, batch_size=batch_size, seed=seed):
        H, cache = forward_feats(params, Xb)
        logits = forward_logits(params, H)
        loss, dlogits = xent_loss_and_grad_logits(logits, yb)
        grads = backward(params, cache, dlogits, freeze_feats=freeze_feats)
        sgd_step(params, grads, lr=lr)
        losses.append(loss)
        accs.append(accuracy(logits, yb))
    return float(np.mean(losses)), float(np.mean(accs))

def eval_model(params, X, y):
    H, _ = forward_feats(params, X)
    logits = forward_logits(params, H)
    loss, _ = xent_loss_and_grad_logits(logits, y)

    # Roughly: compute scores (T^2*d) + apply to V (T^2*d)
    return 2 * T * T * d

def flops_decode_naive(T: int, d: int) -> int:
    # If you recompute attention from scratch at each step t=1..T, cost ~ sum_{t=1..T} 2*t^2*d

Q1. Why do we divide the attention scores by sqrt(d_k)?

Answer: B. The dot products grow with dimension, which pushes the softmax into saturation and kills gradients; scaling keeps the inputs in a healthy range.

  • A, wrong: It has no effect on training; it is only a convention carried over from the original paper.
  • B, right: Without scaling, Q K^T magnitudes grow with d_k, the softmax saturates, and gradients vanish.
  • C, wrong: It makes attention causal by downweighting future positions. Causality comes from the mask, not the scale.
  • D, wrong: It normalizes the output so attention weights sum to one. The softmax does that; scaling shapes the distribution before it.

Q2. In a causal language model, where must the future-position mask be applied?

Answer: C. Before the softmax: masked positions become negative infinity so they contribute zero weight after normalization.

  • A, wrong: After the softmax, by zeroing the weights. The leaked mass stays in the denominator and the model still trains on future information.
  • B, wrong: It does not matter; the mask commutes with the softmax. Softmax is nonlinear, so placement changes the result.
  • C, right: Before the softmax, as negative infinity, so future tokens get exactly zero weight.
  • D, wrong: Only at inference time. Training without the mask teaches the model to cheat.

Q3. A 32-layer model with 32 heads, d_head = 128, serves a 4096-token context in fp16. Roughly how large is the KV cache per sequence, and what does it limit?

Answer: A. About 2.1 GB (2 x 32 x 32 x 128 x 4096 x 2 bytes), and it caps how many concurrent sequences fit in GPU memory.

  • A, right: About 2.1 GB per sequence; cache size, not compute, usually caps concurrent sequences.
  • B, wrong: About 34 GB, which is the size of the materialized score matrix, not the cache.
  • C, wrong: A few megabytes; the cache stores only the latest token. It stores keys and values for every position.
  • D, wrong: It is freed after prefill, so it limits nothing. The cache persists through the whole decode.

Q4. Why can you not swap in a new tokenizer after pretraining?

Answer: D. The embedding matrix is indexed by the old tokenizer's ids; new ids point at rows trained for different tokens, so every embedding becomes wrong.

  • A, wrong: The model architecture hard-codes the vocabulary size in every layer. Only the embedding and output layers depend on it, but that is enough.
  • B, wrong: Tokenizers are not serializable. They are; the problem is semantic, not file format.
  • C, wrong: You can, as long as the new vocabulary is larger. Size is irrelevant; the id-to-token mapping is what breaks.
  • D, right: Embeddings are looked up by id, so a new id mapping scrambles every token's representation.
